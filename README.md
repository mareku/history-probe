## Google Cloud 側の準備(コード外)
- プロジェクト作成 → **Google Drive API を有効化**
- OAuth同意画面: 外部。スコープ `.../auth/drive.file`。**「本番公開」にする**(テスト状態のままだと約7日で認証が切れる)
- OAuthクライアントID(種類: Android): パッケージ名 `com.example.historyprobe` + 署名のSHA-1(`./gradlew signingReport`)
- 各端末に `mareku.hisho@gmail.com` をGoogleアカウントとして追加しておく(コードがこのアカウントを指定する)

## 初回の端末セットアップ
1. インストール → 通知アクセスを許可
2. **端末ラベルを選ぶ**(未設定の間は送信しない。別端末のファイルを上書きしないため)
3. 「今すぐアップロード」→ Drive権限の同意 → フォルダ「視聴履歴」が自動作成される

## 設計書に対する実装判断(要確認)
- PAUSED以外の非再生状態(BUFFERING等)もPAUSEDと同じ扱い(5分続けば閉じる)。STOPPED/NONE/ERRORは即閉じる
- `ended_at` は最後に再生していた時刻(ポーズ放置で閉じたらポーズ開始時刻)
- watched_sec が1秒未満のレコードは保存しない
- 進行中レコードは1分ごと+状態変化時に保存。プロセス死亡後は最終生存時刻で確定
- title は METADATA_KEY_TITLE のみ(display_title は使わない)
- `device` は保存せず出力時に現在のラベルを付ける
- 保持期間(既定30日)を過ぎた送信済みレコードは端末とDrive上のファイルの両方から消える(丸ごと上書きのため)。集約側は30日以内に取り込むこと

## 版の履歴と経緯(2026-11-13)

### v0.3.1-record(採用版)

- v0.3-record からの変更: 同意画面から戻ったとき、結果コード(RESULT_OK)で判断せず、認可を取り直して判定するようにした。Fireの後付けGMSは、同意を進めても RESULT_OK を返さないため。
- 署名キーはプロジェクト内 `keystore/debug.keystore` に固定(SHA-1: 9F:12:BF:50:AA:B2:0C:58:52:D9:D2:B6:B7:44:5B:1E:CD:69:58:8A)。当初の自動生成キー(A7:92…)はビルド環境の入れ替わりで消失したため、このキーで再登録した。以後のビルドはすべてこの署名になる。なお、このGitHubリポジトリには署名キー自体は置いていない。
- Google Cloud登録は完了済み(Drive API有効化、OAuth同意画面は本番公開、公開ページは https://mareku.github.io/history-probe/ )。
- 実機検証: Nothing Phone(正規GMS)では認可とアップロードに成功。Fireタブレットは単体では同意画面が許可を完了できなかった(許可がGoogleアカウント側に記録されなかった)。ただし先にスマホで許可を成立させると、許可はアカウント単位で記録されるため、Fireでも同意画面なしにトークンが取れ、アップロードに成功した。

### v0.3.2-record(未採用・破棄)

- 作ろうとした理由: Fireタブレット単体で最初の許可が取れない問題への対処。新方式(AuthorizationClient)の同意画面が後付けGMS環境では許可をサーバー側に記録できなかったため、従来型Googleサインイン(GoogleSignIn + GoogleAuthUtil でトークン取得)へ自動で切り替えるフォールバックを実装し、ビルドまで完了した。
- 破棄した理由: 切り分けのためにスマホで先に許可したところ、その許可がアカウント単位で効いて Fire でもアップロードできるようになり、フォールバックが不要になったため。本人(mareku)の決定で v0.3.2 は破棄し、v0.3.1 を採用版とした。コードは残していない(この記録のみ)。
